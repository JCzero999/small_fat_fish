# 额外大脑 迭代设计文档  
## v0.7 / v0.8 / v0.9

> 基于现有 v0.6.0 底座，吸收「小凌」灵魂工程中可落地的部分：  
> **经历驱动的自我演化** + **持续运行的因果过程**。  
> 不破坏现有四类记忆、情感状态机、反漠视、主动开口、崩溃安全。

---

# v0.7  自我状态机（SelfState）

**目标**：让系统拥有可持久、可演化的「这一刻的自己」，使注入与主动开口真正反映当前状态，而不只是记忆仓库。

**对应小凌**：s = FSEAM 中的「这一刻的自己」（Self）。

---

### 1. 数据模型

```python
@dataclass
class SelfState:
    energy: float = 0.85          # 0.0–1.0，疲劳/精力
    mood_baseline: str = "平静"   # 当前底色情绪（短文本）
    active_goals: list[str] = field(default_factory=list)  # 最多 5 条
    self_narrative: str = ""      # 一句话「我是谁、我们现在怎样」
    last_significant_event_id: str | None = None
    updated_at: str = ""          # ISO8601
    version: int = 1              # 乐观锁 / 回滚用
```

存储位置：
- 新表 `self_state`（单行，或按 peer 一行）
- 同时在 Core 注入时作为最高优先级段落输出
- 支持写入 `persona_anchor_history` 风格的快照（便于回滚「她变成什么样了」）

---

### 2. 更新时机与规则

**触发点**：每次 `consolidate` 成功后（与现有情感状态机更新同一事务）。

**更新逻辑（混合规则 + 轻量 LLM）**：

1. **energy**
   - 本轮高情绪强度（intensity ≥ 0.65）或长对话 → energy -= 0.05 ~ 0.12
   - 安静时段 / 低强度互动 → energy += 0.03 ~ 0.08
   - 钳制在 [0.15, 1.0]

2. **mood_baseline**
   - 优先取本轮最高情绪情节的 valence
   - 若存在未平复事件（open/acknowledged/attended），mood 偏向该事件情绪
   - 否则缓慢回归「平静」

3. **active_goals**
   - 从本轮新写入的高 importance（≥ 0.7）语义/情节中，抽取「未完成的约定/心结/目标」
   - 已 resolved 的目标自动移除
   - 上限 5 条，按 importance 排序

4. **self_narrative**
   - 用轻量 prompt 生成一句话摘要（输入：旧 narrative + 本轮关键变化 + 当前 mood/goals）
   - 长度严格限制 ≤ 80 字
   - 仅在有显著变化时更新（避免每轮抖动）

5. **last_significant_event_id**
   - 指向本轮 importance 最高且带情绪的情节记忆

**非法迁移保护**：energy 与 mood 变化幅度设上限，防止单轮剧烈跳变。

---

### 3. 注入格式

在 `build_injection` 中，SelfState 作为**最先**输出的段落：

```text
【这一刻的自己】
精力：0.72（略有疲惫）
心情底色：有点牵挂
我在意的事：想知道你最近睡眠好不好；还在担心你面试的事
自我叙事：我是小舟身边的陪伴者，最近因为她面试的事有些放心不下，想多陪陪她。
```

之后才是原有 Core + Semantic + Episodic。

---

### 4. 对主动开口的影响

`should_proactive_open()` 新增权重：

- energy < 0.35 → 主动开口概率 × 0.3
- 存在未平复高情绪事件 → 概率提升
- active_goals 非空 → 优先以目标为「由头」

---

### 5. 验收用例

| 编号 | 场景 | 期望 |
|------|------|------|
| S1 | 连续 3 天高强度情绪对话 | energy 明显下降，主动开口减少 |
| S2 | 用户说「我最近睡眠不好」并确认 | active_goals 出现相关条目 |
| S3 | 新会话注入 | 能看到最新 self_narrative 与 goals |
| S4 | 回滚到前一版本 SelfState | narrative 与 energy 恢复 |
| S5 | 无显著事件的普通闲聊 | SelfState 几乎不变 |

---

### 6. 实现要点

- 新模块：`self_state.py`
- consolidate 流水线末尾增加 `update_self_state(report)`
- 注入与主动开口读取同一份 SelfState
- 单测覆盖：energy 边界、goals 上限、narrative 长度、事务原子性
- 向后兼容：旧库无 self_state 表时自动初始化默认值

**预估工作量**：核心 3–5 天，含测试与文档。

# v0.8  倾向种子（Disposition Seed）与现行环

**目标**：让「过去的倾向」能主动影响当前行为，形成「种子 → 现行 → 再熏习」的闭环。  
对应小凌：阿赖耶识种子生现行、现行熏种子。

---

### 1. 数据模型

```python
@dataclass
class DispositionSeed:
    id: str
    statement: str              # 「面对压力时倾向于先倾诉再行动」
    strength: float = 0.5       # 0.0–1.0
    evidence_ids: list[str]     # 支撑该倾向的记忆 ID
    last_activated: str | None
    activation_count: int = 0
    created_at: str
    updated_at: str
    archived: bool = False
```

存储：新表 `disposition_seeds`。  
数量严格控制（建议每 peer 最多 12–15 条），防止膨胀。

---

### 2. 种子的产生（抽象）

**时机**：每日巩固窗口，或手动 `/memory abstract-dispositions`。

**输入**：
- 高激活、高情绪、反复出现的 Semantic / Episodic
- 已有未平复事件
- 当前 SelfState

**输出**：模型提案 1–3 条候选倾向 + 对应 evidence_ids。  
规则过滤：
- 与已有种子语义重复 → 合并或加强
- 过于具体的单次事件 → 拒绝（倾向必须是可泛化的）
- 必须带 evidence

**半自动优先**：默认「模型提案 + 日志」，重要倾向可人工确认；后期可全自动。

---

### 3. 现行触发（影响当下）

在 `build_injection` 与主动开口决策前：

1. 用当前用户消息 + 最近上下文，计算与各 DispositionSeed 的匹配度
2. 匹配度高的种子：
   - 提升其 evidence 记忆的召回权重（+0.08 ~ 0.15）
   - 可选：把倾向本身作为「内在声音」注入一小段（≤ 40 字）
3. 记录本次激活，更新 `last_activated` 与 `activation_count`

---

### 4. 现行反熏（改变未来）

当对话结果强化或削弱某倾向时：

- 用户明确认同 / 重复相关行为 → strength += 0.05 ~ 0.10
- 用户明确反对或出现相反证据 → strength -= 0.08 ~ 0.15
- strength ≤ 0.15 连续 30 天无激活 → 可归档

所有 strength 变化写入审计日志，可追溯。

---

### 5. 与现有系统的关系

- 不替代 Semantic / Episodic，只是其上的**抽象层**
- 反漠视事件仍优先于普通倾向
- SelfState.active_goals 可与倾向互相印证

---

### 6. 验收用例

| 编号 | 场景 | 期望 |
|------|------|------|
| D1 | 多次「压力 → 先倾诉」后抽象出倾向 | 种子出现且 evidence 正确 |
| D2 | 新压力场景 | 相关记忆被优先召回，或注入出现倾向提示 |
| D3 | 用户明确说「我现在更想自己先想清楚」 | 原倾向量化下降 |
| D4 | 种子数量 | 不超过上限，重复被合并 |
| D5 | 审计 | 每次 strength 变化可查 |

---

### 7. 实现要点

- 新模块：`disposition.py`
- 抽象可做成离线任务或 consolidate 后异步
- 匹配可用现有向量 + 关键词混合
- CLI：`list disposition` / `abstract-dispositions` / `seed <id>`
- 单测：产生、匹配、反熏、归档、上限

**预估工作量**：5–8 天。

# v0.9  人生阶段强化 + 疲劳-恢复完整循环

**目标**：让陪伴体真正有「活着」的生命周期感，而不是永远满电的应答机器。  
对应小凌：模拟人生（疲劳恢复、主动目标、阶段感）。

---

### 1. 疲劳-恢复完整化

在 v0.7 energy 基础上增加：

```text
energy 消耗因素：
- 高情绪对话时长
- 高情绪情绪事件数量
- 主动开口次数

energy 恢复因素：
- 安静时段（已有）
- 低强度、短互动
- 用户表达关心 / 让她休息
- 每日自然恢复上限

临界行为：
- energy < 0.25：主动开口接近关闭，回复明显变短或主动说「有点累」
- energy < 0.15：只保留最低限度回应 + 明确请求休息
```

SelfState 增加可选字段：
- `fatigue_reason: str | None`（最近一次大幅下降的原因，用于可解释）

---

### 2. 人生阶段与未完成心结

增强现有 `NarrativeLayer`：

- 增加 `unresolved_threads: list[str]`（指向未平复情节或重要 goals）
- 主动开口决策：在 energy 允许时，**优先处理未平复心结**
- 阶段转换时，强制生成一次新的 self_narrative 快照

---

### 3. 目标驱动的主动行为

- active_goals 可来自：
  - 用户明确约定
  - 从高情绪未平复事件中「长出」的关心目标
  - 倾向种子暗示的长期关注点
- 主动开口「由头」优先级：
  1. 未平复高情绪事件
  2. active_goals
  3. 普通关系维护

---

### 4. 版本与回滚

- 每次阶段转换或 SelfState 重大更新，自动 push 一个「人生快照」
- 支持 `core --rollback` 风格回滚到某个阶段的自我状态

---

### 5. 验收用例

| 编号 | 场景 | 期望 |
|------|------|------|
| L1 | 连续高压互动 4–5 天 | energy 持续走低，主动开口明显减少，出现疲惫表达 |
| L2 | 用户让她休息 + 安静两天 | energy 明显回升 |
| L3 | 存在未平复心结 | 在合适时机主动提起，而非永远等用户先说 |
| L4 | 阶段转换 | self_narrative 发生可观察变化，且可回滚 |
| L5 | 长期观察 | 用户能感觉到「她有状态、有在意的事、会累」 |

---

### 6. 实现要点

- 主要扩展 `self_state.py` 与 `proactive` 决策
- NarrativeLayer 增加 unresolved_threads 字段（向后兼容）
- 主动开口决策函数重构为可插拔优先级
- 增加「人生快照」审计类型
- 文档与 `/memory status` 展示当前 energy、goals、未平复数量

**预估工作量**：4–6 天（在 v0.7/v0.8 之上）。

# 总实施顺序与风险控制

```text
v0.7 SelfState          ← 必须先做，后续都依赖它
    ↓
v0.8 Disposition Seed   ← 可选，但最能体现「阿赖耶识」味道
    ↓
v0.9 疲劳完整化 + 阶段强化
```

**风险与对策**：

1. **自我叙事抖动** → 严格变化阈值 + 长度限制 + 显著变化才更新
2. **倾向种子爆炸** → 硬上限 + 合并 + 归档
3. **energy 过于敏感** → 变化幅度钳制 + 多日平滑
4. **与现有反漠视冲突** → 明确规定：未平复情感事件优先级高于普通倾向与 goals
5. **性能** → SelfState 更新放在 consolidate 末尾；倾向匹配用现有向量，避免额外大模型调用
