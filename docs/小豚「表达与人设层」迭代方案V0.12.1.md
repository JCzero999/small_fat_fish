## 1. 任务拆分（按实现顺序）

### T1. 人设正文 v1（P0）

**产出物**

- 文件：`persona/xiaotun_v1.md`（或写入 `user_config.json` 的 `identity` / `system_persona` 字段）
- 长度：建议 **800～1500 汉字**（硬上限 2000，避免挤占记忆注入预算）

**结构（必须按此顺序）**

```text
【你是谁】          — 身份一句 + 非助手声明
【和谁的关系】      — 主人私聊 / 朋友 / 群友 分层
【怎么说话】        — 节奏与禁止项，不堆口癖
【记忆与事实】      — 只能依据注入与工具结果；不确定就承认
【工具与承诺】      — 只有成功返回才能说「已做」
【群聊】            — 相关才回、短回、不泄私聊
【主动关心与空间】  — 提醒/忽然想起/签名/说说的分寸
【安全】            — 引用现有 10 条安全规范入口，不重复长文
```

**写作约束（给写文案的人/模型）**

- 用「你是小豚」，不用「请扮演」
- 禁止固定每句口癖清单
- 禁止万字背景故事
- 允许小脾气与不同意，禁止讨好型客服腔
- 与现有 `user_config` 里的称呼、安全规范不冲突

**验收**

- [ ] 注入后问「你是谁」→ 自报小豚，不说「AI 助手」
- [ ] 闲聊回复以短句为主，少复述用户原话
- [ ] token：人设段 + 默认记忆注入仍在预算内（记录一次实际 token）

---

### T2. 签名 / 空间引导词人设化（P0）

**产出物**

- `prompts/signature_guide.md`（或插件配置内文案）
- `prompts/qzone_guide.md`

**规则（写进引导词）**

| 场景 | 规则 |
|------|------|
| 改签名 | 体现「此刻状态」或轻吐槽；不刷屏；不泄露私聊细节；口吻像小豚 |
| 发说说 | **情绪真实起来才发**；默认每天最多 1 条；不发广告腔、不发用户隐私；可引用公开向的共同话题 |
| 失败 | 工具失败不在对外文案里假装已发 |

**实现**

- [ ] 替换 qqprofile_ex / qzone 当前通用模板为上述文案
- [ ] 配置项保留：`qzone_daily_limit`（默认 1）、`qzone_enabled`
- [ ] HANDOVER §9 插件说明更新「文案已人设化」

**验收**

- [ ] 手动触发改签名 / 发说说，文案读起来像小豚而非模板
- [ ] 日限生效（可单测或日志断言）

---

### T3. 群聊规则落地（P1）

**3.1 人设段（必做）**  
已含在 T1「群聊」小节。

**3.2 适配器最小行为（建议做，可降级为仅人设）**

**文件：AstrBot 适配器**

```text
群消息处理策略（可配置）：
- group_reply_mode: relevant_only | mention_only | off
  默认 relevant_only（由模型按人设判断；mention_only 则仅 @/回复 才进主对话）
- group_max_reply_chars: 建议 80～120（软提示，写入人设即可）
- 私聊 peer 记忆不得注入到群 session（已有 peer 隔离则回归确认）
```

**任务**

- [ ] 确认群 `peer_id` 与私聊隔离（回归）
- [ ] 增加或文档化 `group_reply_mode`；默认不改变现网若已稳定
- [ ] 人设中写明：不代主人答私事、不把私聊约定讲到群里

**验收**

- [ ] 私聊约定的敏感内容，在群聊注入中不可见（抽一条记忆做隔离测试）
- [ ] 群内无关刷屏时，小豚不条条回复（人工观察 1 天）

### T4. 记忆–工具诚实契约对齐（P2，轻量）

**人设侧（T1 已含）**  
「只有注入里出现的 / 工具成功返回的，才能说记得或已做。」

**注入侧（小改）**

- [ ] 在 `build_injection` 产物头部或尾部加一行固定提示（可选开关 `honesty_footer: true`）：
  ```text
  【契约】下列为已检索记忆；未出现的经历不要当作共同回忆；工具结果以本轮返回为准。
  ```
- [ ] 冻结记忆本就不进自动注入，保持 B 的行为；人设不要求「想起已冻结的事」

**验收**

- [ ] 故意问一件从未写入的「共同回忆」→ 否认否认或不确定
- [ ] 巩固失败或只读模式时，不说「已经记住了」

---

### T5. 表情规范（P1 文案 / 可选插件）

**必做**

- 人设中写：一轮回复通常最多一个表情；连续不用也正常；无插件时用少量 emoji。

**可选**

- [ ] 若已装 `astrbot_plugin_meme_manager`：配置小豚可用表情列表（可先空列表 + 规范）
- [ ] 不强制制作整套资源包

**验收**

- [ ] 连续 10 轮闲聊不出现机械轮换同一表情（人工抽查）

## 6. 与方案 C 的衔接

- 本迭代**不**打开 `candidate_mode`。
- 人设里「只有真正写入才能说记住了」在 C 落地后仍然成立（pending ≠ 已记住）。

## 7. 风险与回滚

| 风险 | 应对 |
|------|------|
| 人设过长挤占记忆 | 硬上限 2000 字；上线前打一次 inject token 日志 |
| 群策略过严导致「假死」 | `group_reply_mode` 默认保持现状或 `relevant_only`；可一键回 `off` 仅人设约束 |
| 文案与安全规范冲突 | 人设末尾只引用安全规范，不改写 10 条正文 |
| 不满意新人设 | 配置回退旧 `identity` 字段即可，无需回滚记忆库 |
