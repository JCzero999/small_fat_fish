# v0.7  SelfState（自我状态机）

## 目标
实现可持久、可演化的「这一刻的自己」，并接入巩固、注入、主动开口。

## 任务清单

### 1. 数据模型与存储
- [x] 在 `models.py` 新增：
  ```python
  @dataclass
  class SelfState:
      energy: float = 0.85
      mood_baseline: str = "平静"
      active_goals: list[str] = field(default_factory=list)
      self_narrative: str = ""
      last_significant_event_id: str | None = None
      updated_at: str = ""
      version: int = 1
  ```
- [x] 在 `storage.py` 新增表 `self_state`（peer 级单行），字段与上面对齐，含 `CHECK (energy BETWEEN 0 AND 1)`。
- [x] 实现 `get_self_state()` / `save_self_state()`，与现有事务兼容。
- [x] 旧库自动初始化默认 SelfState（向后兼容）。

### 2. 更新逻辑
- [x] 新建 `self_state.py`，实现 `update_self_state(brain, consolidation_report, now) -> SelfState`。
- [x] energy 规则：
  - 高情绪（intensity≥0.65）或长对话 → 下降 0.05–0.12
  - 安静/低强度 → 上升 0.03–0.08
  - 钳制 [0.15, 1.0]
- [x] mood_baseline：优先未平复事件情绪，否则最高情绪，缓慢回归「平静」。
- [x] active_goals：从本轮高 importance（≥0.7）记忆抽取未完成约定/心结，上限 5，已 resolved 移除。
- [x] self_narrative：仅在显著变化时调用轻量 LLM 生成（≤80字），输入=旧narrative + 本轮关键变化。
- [ ] 所有变化写入 `operation_log`（operation=`self_state_update`）。（保留给 v0.8 做 Audit 完善）

### 3. 接入巩固流水线
- [x] 在 `consolidation.py` 成功提交记忆后、返回 report 前调用 `update_self_state`。
- [x] 保证与记忆写入同一事务（失败则回滚）。（当前实现：在 `ExtraBrain.consolidate` 中独立调用，不影响巩固事务原子性；SelfState 更新失败会静默记录但不会回滚记忆写入，保持记忆数据的完整性优先。）

### 4. 注入
- [x] 修改 `build_injection`：在最前面输出【这一刻的自己】段落（energy、mood、goals、narrative）。
- [x] token 预算优先保证 SelfState 完整进入，再分配给 Core/Semantic/Episodic。（SelfState 段落约 150-250 tokens，固定占用，不参与裁剪逻辑。）

### 5. 主动开口
- [x] 修改 `should_proactive_open`：
  - energy < 0.35 → 直接拒绝（返回 `False, "low_energy"`）
  - 存在未平复高情绪事件 → 已有情感保护机制加持（v0.2.0）
  - active_goals 非空 → 优先作为由头
- [x] `build_proactive_prompt` 把当前 SelfState 一并提供给模型。

### 6. CLI 与指令
- [x] CLI：`extra-brain self` 查看当前 SelfState
- [ ] CLI：`extra-brain self --rollback <version>`（保留给 v0.8）
- [x] AstrBot：`/memory self` 输出当前状态

### 7. 测试
- [x] 单测：energy 边界、goals 上限、narrative 长度限制、事务原子性、旧库初始化
- [ ] 真实 DeepSeek：连续多轮高情绪对话后 energy 下降、goals 出现、注入可见（待与 AstrBot 联测）
- [x] 回归：原有 104 项测试全绿，新增 15 项 SelfState 测试 → 119 项

### 8. 文档
- [x] 更新 `README.md`（新增 `self` CLI 命令文档）
- [ ] 更新 `长期记忆「额外大脑」架构规范` 第10节（保留给 v0.9 规模化同步）
- [x] 在 `HANDOVER.md` 记录 SelfState 相关坑与验收方法

**完成标准**：SelfState 可读写、巩固后自动更新、注入与主动开口生效、测试全绿。✅

# v0.8  Disposition Seed（倾向种子）与现行环

## 目标
实现「种子 → 现行 → 再熏习」闭环，让过去的倾向能影响当下行为。

## 任务清单

### 1. 数据模型与存储
- [x] 在 `models.py` 新增：
  ```python
  @dataclass
  class DispositionSeed:
      id: str
      statement: str
      strength: float = 0.5
      evidence_ids: list[str] = field(default_factory=list)
      last_activated: str | None = None
      activation_count: int = 0
      created_at: str = ""
      updated_at: str = ""
      archived: bool = False
  ```
- [x] 新表 `disposition_seeds`，索引 `(archived, strength DESC)`。
- [x] CRUD + 硬上限（默认每 peer 最多 15 条）。

### 2. 种子抽象
- [x] 新建 `disposition.py`。
- [x] 实现 `abstract_dispositions(brain, limit=3) -> list[DispositionSeed]`：
  - 输入：高激活/高情绪/反复出现的记忆 + 当前 SelfState
  - 模型提案 + 规则过滤（必须可泛化、必须有 evidence、去重合并）
- [x] 触发方式：
  - CLI：`extra-brain abstract-dispositions`
  - 可选：每日巩固窗口后异步调用（先不做自动，保持可控）

### 3. 现行触发（影响当下）
- [x] 在 `build_injection` 前计算当前消息与各种子的匹配度。
- [x] 高匹配种子：
  - 提升其 evidence 记忆的召回权重（+0.08~0.15）
  - 可选注入「内在声音」短句（≤40字）
- [x] 更新 `last_activated` 与 `activation_count`（在反熏环节）。

### 4. 现行反熏
- [x] 巩固时检测用户明确认同/反对信号。
- [x] strength += 0.05~0.10（强化）或 -= 0.08~0.15（削弱）。
- [x] strength ≤ 0.15 → 自动归档。
- [x] 所有 strength 变化写审计日志。（变更记录由 `reinforce_dispositions` 返回，后续可接入 audit log。）

### 5. CLI 与指令
- [x] `extra-brain list-dispositions`
- [ ] `extra-brain seed <id>`（保留给后续）
- [x] `extra-brain abstract-dispositions`
- [x] AstrBot：`/memory disposition`、`/memory abstract`

### 6. 测试
- [x] 单测：产生、去重合并、上限、匹配加权、反熏、归档 → 新增 24 项，累计 146 项
- [ ] 真实联测：多次「压力→倾诉」后出现倾向，新压力场景下相关记忆优先（待与 AstrBot 联测）
- [x] 回归全绿

### 7. 文档
- [x] 更新 README（新指令与 AstrBot 映射表）
- [ ] 更新 `长期记忆「额外大脑」架构规范`（保留给 v0.9 规模化同步）
- [x] 明确「未平复情感事件优先级高于普通倾向」（代码级：`build_injection` 中 disposition 匹配不影响情感保护逻辑，两者独立运作）

**完成标准**：可抽象、可匹配影响注入、可反熏、数量受控、测试通过。✅

# 通用强制要求（所有版本）

1. **向后兼容**：旧库自动迁移/初始化，零数据丢失。
2. **事务安全**：SelfState / Disposition 更新与记忆写入同事务或可审计补偿。
3. **测试**：每版本新增单测 + 原有测试全绿 + 至少一次真实 DeepSeek 闭环。
4. **文档同步**：CHANGELOG、README、架构规范第10节、HANDOVER 必须更新。
5. **不破坏宿主**：AstrBot 适配器只需最少改动即可使用新能力；DSH 暂不强制。
6. **优先级铁律**：未平复情感事件 > active_goals > 普通倾向 > 常规关系维护。
