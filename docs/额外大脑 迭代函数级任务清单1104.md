# B2. 牢固度更新规则

**文件：建议新建 `src/extra_brain/solidity.py`（或放入现有 retention 模块）**

## 2.1 配置

```python
@dataclass
class SolidityConfig:
    freeze_threshold: float = 0.35      # retrievability 低于此且非保护 → frozen
    max_stability: float = 365.0
    initial_stability: float = 1.0
    review_window_hours: float = 24.0   # 窗口内多次想起只算一次加固
    stability_gain: float = 0.35        # 每次有效复习的稳定性增益系数（可调）
    min_stability: float = 0.5
```

可挂在 `MemoryConfig` 下，默认值即可用。

## 2.2 核心函数

```python
def compute_retrievability(
    stability: float,
    last_review: str | None,
    now: datetime,
) -> float:
    """
    简化 FSRS 思想：
    - 无 last_review → 返回当前 stored retrievability 或 1.0
    - elapsed_days = (now - last_review).total_seconds() / 86400
    - retrievability = exp(-elapsed_days / max(stability, min_stability))
    - clamp 到 [0, 1]
    """

def apply_review(
    mem: SemanticMemory | EpisodicMemory,
    now: datetime,
    config: SolidityConfig,
) -> SemanticMemory | EpisodicMemory:
    """
    「想起」加固：
    - 若 last_review 在 review_window_hours 内 → 不重复加固，仅可刷新 retrievability=1.0（可选）
    - 否则：
        review_count += 1
        stability = min(max_stability, max(min_stability, stability * (1 + stability_gain)))
        或更稳的加法/对数增长，避免爆炸
        retrievability = 1.0
        last_review = now.isoformat()
        frozen = False
    - 返回更新后的 mem（不负责落库）
    """

def apply_decay_and_freeze(
    mem: SemanticMemory | EpisodicMemory,
    now: datetime,
    config: SolidityConfig,
    *,
    protected: bool,
) -> SemanticMemory | EpisodicMemory:
    """
    时间流逝：
    - 重算 retrievability = compute_retrievability(...)
    - 若 retrievability < freeze_threshold 且 not protected → frozen = True
    - 保护项：可更新 retrievability，但 frozen 保持 False
    """

def batch_decay(
    brain: ExtraBrain,
    peer_id: str,
    now: datetime,
    config: SolidityConfig | None = None,
) -> dict:
    """
    批量更新本 peer 下所有 Semantic + Episodic 的 retrievability / frozen。
    返回摘要：{updated, newly_frozen, skipped_protected}
    写库需走现有审计 / 事务路径。
    """
```

**稳定性增长建议（防爆炸）：**

```text
stability_new = min(
    max_stability,
    stability + stability_gain * (1 + log1p(review_count))
)
```

或保持简单乘法但设硬顶，实现时二选一并写单测锁定。

```python
    payload: dict                        # 接近正式 Memory 的字段草稿（无正式 id）

    source_message_ids: list[str] = field(default_factory=list)
    confidence: float = 0.0              # 抽取模型给出的置信度
    reason: str = ""                     # 为何认为值得记
    status: str = "pending"              # pending | approved | rejected | expired
    created_at: str = ""
    decided_at: str | None = None
    decided_by: str | None = None        # user | model_auto | system
    expires_at: str | None = None        # 超时未处理则 expired
```

**约束：**
- `status ∈ {pending, approved, rejected, expired}`
- `kind ∈ {semantic, episodic, style, goal}`
- `0 ≤ confidence ≤ 1`
- 每 peer 同时 `pending` 上限可配（默认 20）

## 1.2 配置

```python

class AutonomyConfig:
    candidate_mode: bool = False           # 总开关，默认关（保持现网自动写入）
```

# C3. 巩固管线改造

## 3.1 模式分支

**文件：巩固入口 `consolidate`**

```python
def consolidate(..., *, autonomy: AutonomyConfig | None = None) -> ConsolidationReport:
    """
    若 not candidate_mode：
        行为与当前完全一致（直接写 Semantic/Episodic/...）
    若 candidate_mode：
        1. 照常跑抽取，得到 draft 条目
        2. confidence < low_confidence_drop → 丢弃
        3. 其余 → 转为 CandidateMemory，status=pending
        4. 若 auto_approve_enabled 且通过自动批准规则 → 直接 promote
        5. 报告中增加 candidates_created / auto_approved / dropped
    """
```

**注意：**  
冲突检测、Core 清理、情感状态机、牢固度（B）等**正式写入路径**保持不变；候选阶段只做「是否进库」的闸门。

# C7. 与 A/B 的边界

| 能力 | 关系 |
|------|------|
| A1 约定 goals | goal 类可先入候选；批准后再进 `active_goals` |
| A2 忽然想起 | 只从**已批准正式库**中选，忽略候选 |
| A3 影子模式 | 无关；候选闸门独立 |
| B 牢固度 | 仅对正式写入的记忆计算；候选无 stability |
| 冲突 / Core 清理 | 发生在 promote 时的正式写入路径，逻辑不变 |

# C8. 测试矩阵

## 单测

- [ ] `candidate_mode=False`：巩固行为与改造前一致（回归）
- [ ] 低置信直接丢弃，不进 pending
- [ ] 高置信 + auto_approve → 直接正式写入，status=approved
- [ ] 普通置信 → pending；promote 后库中有对应 Memory
- [ ] reject 后不出现在正式 list
- [ ] TTL 到期 → expired
- [ ] pending 数量触顶时的策略（拒绝新候选或淘汰最旧，需固定一种并测）
- [ ] 审计日志含 created / approved / rejected

## 真实联测

1. 打开 `candidate_mode`，多轮对话后出现 pending  
2. `/memory pending` 可见；`approve` 后新会话注入能召回  
3. `reject` 后永不出现在注入中  
4. 关闭 `candidate_mode` 后恢复「巩固即写入」
