```markdown
# 长期记忆「额外大脑」架构规范 v0.9
> 面向陪伴型 AI 的可落地长期记忆系统设计  
> 目标：让模型在任意新上下文窗口中，仍能维持连续的身份、关系与记忆  
> 适用范围：通用 LLM Agent / DeepSeek Harness + QQ 等场景  
> 设计原则：第一性原理 + 对抗式审查后的精炼版本

---

## 0. 第一性原理（First Principles）

### 0.1 核心问题定义
- 大模型的上下文窗口 = **工作记忆**（容量有限、易丢失）
- 陪伴型 AI 需要的是**跨会话的持续身份与关系连续性**
- 因此必须在模型外部构建一套「额外大脑」，负责：
  1. 深度加工（Encoding）
  2. 结构化持久存储（Storage）
  3. 主动巩固与衰减（Consolidation & Decay）
  4. 精准检索与注入（Retrieval & Injection）

### 0.2 不可妥协的约束
1. **工作记忆必须保持干净**：注入内容必须高度相关且总量可控，否则会稀释推理能力。
2. **记忆必须可解释、可审计**：不能变成黑盒向量堆。
3. **情绪与关系价值优先于事实**：陪伴场景下，「被记住的感觉」比「记住了什么」更重要。
4. **遗忘是功能，不是缺陷**：必须有明确的衰减与归档机制，防止记忆膨胀和噪声积累。
5. **深度加工必须强制执行**：简单摘要或原文存储无法产生真人感。

### 0.3 人类记忆研究的可迁移精华
- Atkinson-Shiffrin：分层存储（工作 vs 长期）
- Baddeley：工作记忆多组件（不同类型信息分开处理）
- Craik & Lockhart：加工深度决定记忆强度
- Method of Loci：结构化组织 + 强烈线索绑定
- Ebbinghaus + Spaced Repetition：遗忘曲线 + 主动巩固

## 1. 对抗式审查（Adversarial Review）与关键修正

### 1.1 对上一版草案的尖锐质疑

| 质疑点 | 风险 | 修正措施 |
|--------|------|----------|
| 重要性评分完全依赖模型 | 模型可能高估闲聊、低估真正关系节点 | 引入「硬规则 + 模型评分」双轨，并设置人工/规则可覆盖 |
| 情节记忆与语义记忆边界模糊 | 导致重复存储和检索冲突 | 明确：情节 = 带时间的互动事件；语义 = 可跨时间复用的稳定事实/关系 |
| 衰减公式过于简单 | 重要但很久未提的记忆会错误消失 | 引入「保护期」与「关系核心记忆永不衰减」机制 |
| 检索只靠向量相似度 | 容易召回语义相关但关系无关的内容 | 强制加入 importance × recency × emotion_match 加权，并支持实体过滤 |
| Core Memory 可能膨胀 | 破坏工作记忆干净原则 | 严格限制 Core 体积，并设立「晋升/降级」规则 |
| 没有冲突解决机制 | 用户前后说法矛盾时记忆会混乱 | 增加「冲突检测 + 置信度更新 + 时间线优先」规则 |

### 1.2 修正后的设计立场
- **少而精** 优于 多而全
- **可解释结构** 优于 纯向量
- **关系与情绪优先** 优于 事实堆砌
- **主动遗忘与主动巩固** 同等重要

## 3. 存储结构（Schema）

### 3.1 Core Memory（严格控制体积）

```json
{
  "version": "1.0",
  "last_updated": "ISO8601",
  "identity": {
    "name": "string",
    "persona_core": "string（不超过150字）",
    "relationship_definition": "string",
    "speaking_style": "string"
  },
  "user_stable_profile": {
    "preferred_name": "string",
    "key_traits": ["string"],
    "core_preferences": ["string"],
    "important_life_facts": ["string"]
  },
  "active_threads": [
    {
      "id": "thread_xxx",
      "summary": "string",
      "status": "open|watching|closed",
      "last_mentioned": "ISO8601"
    }
  ],
  "protected_memories": ["memory_id"]   // 永不衰减的核心记忆ID
}
```

**硬性限制**：
- 整体序列化后建议 ≤ 1200 tokens
- 任何新增必须经过「是否值得进入 Core」的判断

### 3.2 Semantic Memory（事实与关系）

```json
{
  "id": "sem_YYYYMMDD_xxx",
  "type": "fact|preference|relationship|goal|trait",
  "subject": "string",
  "predicate": "string",
  "object": "string",
  "detail": "string",
  "importance": 0.0-1.0,
  "emotion_valence": "positive|neutral|negative|mixed",
  "emotion_intensity": 0.0-1.0,
  "confidence": 0.0-1.0,
  "source_episodic_ids": ["ep_xxx"],
  "created_at": "ISO8601",
  "last_activated": "ISO8601",
  "activation_count": 0,
  "decay_score": 1.0,
  "conflict_flag": false,
  "protected": false
}
```

### 3.3 Episodic Memory（情节事件）

```json
{
  "id": "ep_YYYYMMDD_xxx",
  "timestamp": "ISO8601",
  "summary": "string（1-3句）",
  "key_moments": ["string（关键原话或高度还原时刻）"],
  "emotions": ["string"],
  "importance": 0.0-1.0,
  "related_semantic_ids": ["sem_xxx"],
  "participants": ["user", "agent"],
  "raw_reference": "optional path or session_id",
  "decay_score": 1.0,
  "protected": false
}
```

### 3.4 Style & Procedural Memory

```json
{
  "id": "style_xxx",
  "observation": "string",
  "category": "expression|preference|interaction_habit|boundary",
  "importance": 0.0-1.0,
  "examples": ["string"],
  "last_observed": "ISO8601"
}
```

## 4. 深度抽取 Prompt（强制使用）

```text
你是一个极度严谨的长期记忆整理官。你的唯一任务是从对话中提取对「持续陪伴关系」真正有长期价值的信息。

对话内容：
{conversation}

输出要求：
- 只输出合法 JSON，不要任何解释或 markdown
- 严格遵守下面的结构
- 如果没有值得记录的内容，对应数组必须为空
- 重要性评分必须保守：只有真正影响关系 continuity 的才给高分

{
  "core_candidate_updates": {
    "user_profile_changes": [],
    "relationship_changes": [],
    "new_or_updated_threads": [],
    "should_promote_to_core": []
  },
  "semantic_facts": [
    {
      "type": "fact|preference|relationship|goal|trait",
      "subject": "",
      "predicate": "",
      "object": "",
      "detail": "",
      "importance": 0.0,
      "emotion_valence": "positive|neutral|negative|mixed",
      "emotion_intensity": 0.0,
      "confidence": 0.0
    }
  ],
  "episodic_events": [
    {
      "summary": "",
      "key_moments": [],
      "emotions": [],
      "importance": 0.0
    }
  ],
  "style_observations": [
    {
      "observation": "",
      "category": "expression|preference|interaction_habit|boundary",
      "importance": 0.0
    }
  ],

提取铁律：
1. 情绪强度 + 关系意义 > 信息量
2. 一次性闲聊和技术细节默认不记录，除非用户明确赋予高情绪价值
3. 用户前后矛盾时必须在 conflicts_detected 中标注
4. importance ≥ 0.8 的条目需要有明确理由支撑（在 detail 或 summary 中体现）
```

## 5. 巩固流程（Consolidation Pipeline）

### 5.1 触发条件
- 会话结束
- 累计新消息超过阈值
- 每日固定巩固窗口（模拟睡眠）
- 高重要性新记忆写入后

### 5.2 处理步骤（必须按顺序）

1. **抽取**：使用第4节 Prompt
2. **冲突检测与解决**
   - 新事实与旧事实矛盾 → 降低旧事实 confidence，或标记 conflict，以时间较新 + 置信度更高者为准
3. **去重与合并**
   - 语义高度相似的事实合并，保留更高 importance 和更新的时间戳
4. **衰减计算**
   ```
   若 protected == true → decay_score 保持 1.0
   否则：
   decay_score = importance * exp(-λ * days_since_last_activated) * (1 + 0.1 * log(1 + activation_count))
   ```
   建议 λ 初始值 0.05~0.08
5. **晋升 / 降级**
   - 高 importance + 多次激活 + 关系相关 → 考虑写入 Core 的 protected_memories 或 user_stable_profile
   - 低 decay_score 且长期未激活 → 归档或删除
6. **更新向量索引**（对 summary + key_moments + detail 做 embedding）
7. **写回存储**

---

## 6. 检索与注入策略

### 6.1 检索流程
1. 始终注入完整 Core Memory
2. 用「当前用户消息 + 最近3-5轮上下文」生成查询向量
3. 向量检索候选（Semantic + Episodic）
4. 综合打分：
   ```
   final_score = 
     0.40 * semantic_similarity +
     0.25 * importance +
     0.20 * recency_boost +
     0.15 * emotion_match
   ```
5. 实体/关键词硬过滤（可选）
6. 取 Top-K（建议 Semantic 4~6 条，Episodic 1~3 条）

### 6.2 注入原则
- 总量严格控制，优先保证推理空间
- 情节记忆优先带 key_moments（原话感更强）
- 低分记忆宁可不注入

## 7. 实现约束与最小可行路径

### 7.1 必须实现的最小集合（MVP）
1. Core Memory 读写与注入
2. Semantic 事实存储 + 简单向量检索
3. 会话结束后的抽取与写入
4. 基础衰减与 importance 过滤

### 7.2 进阶能力（建议第二阶段）
- 完整 Episodic
- 冲突检测
- 自动巩固任务
- Style Memory
- 保护记忆与晋升机制

### 7.3 技术建议
- 存储：SQLite（结构化）+ 本地向量库（chroma / faiss / 简单 numpy）
- 所有记忆操作必须可日志化，便于调试与回滚
- 抽取 Prompt 的输出必须做 JSON schema 校验

## 8. 成功标准（Acceptance Criteria）

一个合格的实现至少应满足：
1. 新会话开始时，模型能自然提及过去的重要关系节点或情绪时刻
2. 无关闲聊不会污染长期记忆
3. 用户修正自己的说法后，旧错误记忆能被正确降权或标记
4. Core Memory 体积始终受控
5. 长时间不互动后，低价值记忆会自然淡化，高价值记忆仍可被召回

## 9. 给实现者的最终指令

当你拿到这份文档后：
1. 先实现 MVP（第7.1节）
2. 用真实多轮对话测试「被记住的感觉」
3. 根据测试结果微调 importance 阈值、衰减 λ、检索权重
4. 再逐步加入冲突处理与自动巩固
5. 任何偏离本规范的设计，必须先说明违背了哪条第一性原理

本规范的目标不是「记住尽可能多」，而是**用最少的记忆，维持最强的关系连续性与真人感**。

### 10.5 对规范的偏离与说明

按第 9 节要求，偏离必须说明违背了哪条第一性原理：

1. **`archived` 及情节记忆的 `last_activated`/`activation_count` 为新增字段**——是对第 0.2 节「遗忘是功能」和「Meta Layer」的可操作化补充，不违背任何第一性原理，反而落实了主动遗忘与激活记录。
2. **默认向量用本地特征哈希而非神经网络 embedding**——满足 7.3「简单向量」；若要更强跨语言语义召回，实现 `EmbeddingProvider` 协议替换并 `reindex()`，不改变接口。
3. **token 预算用保守估算而非绑定 tokenizer**——为保证零依赖与可移植性；可通过调小 `injection_token_limit` 留出余量。不违背「工作记忆必须干净」原则（默认值已足够保守）。
4. **定时巩固与消息累计阈值由宿主触发**——第 5.1 节四种触发条件统一映射为对 `consolidate` 的一次调用；库不启动常驻调度线程，避免与宿主（DeepSeek Harness / QQ）生命周期冲突。
