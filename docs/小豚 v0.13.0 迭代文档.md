# 小豚 v0.13.0 迭代文档  
## 主场迁移：独立 Chat Shell + Agent API

**版本号：`v0.13.0`**  
**文档角色：** 交给 WorkBuddy / 实现 Agent 直接执行的规格  
**前置版本：** `v0.12.0`（A 生活感 + B 牢固度已上线）  
**本版本主题：** 主会话从「仅 QQ」迁到「独立壳为主、QQ 为辅」；人与 AI 编程工具共用同一套后端

## 1. 第一性原理（实现时不得违反）

1. **记忆唯一真相源** = 现有 `extra_brain` SQLite（按 peer）；禁止在前端另存对话当长期记忆。  
2. **主场** = 本版 Web Shell + API；QQ 可继续跑，但文档与默认引导指向壳。  
3. **人机同权** = UI 能做的巩固/注入预览，API 必须能做。  
4. **默认本机** = 服务只绑 `127.0.0.1`；带本地 token。  
5. **零强制迁移** = 旧 QQ peer 库不动；主壳使用独立默认 `peer_id`。

## 2. 架构（必须按此落地）

```text
┌─────────────────────────────────────────┐
│  Chat UI (静态或简易后端托管)              │
│  浏览器打开 http://127.0.0.1:<port>/      │
└─────────────────┬───────────────────────┘
                  │ HTTP / WS（本版允许仅 HTTP 轮询或一次一回）
┌─────────────────▼───────────────────────┐
│  shell 层（可与 sidecar 同进程或薄封装）    │
│  POST /v1/chat                          │
│  POST /v1/consolidate                   │
│  GET  /v1/inject_preview                │
│  GET  /v1/health                        │
│  GET  /v1/core 等调试只读                 │
└─────────────────┬───────────────────────┘
                  │ 调用现有 Python API
┌─────────────────▼───────────────────────┐
│  extra_brain（v0.12 内核，不改语义）       │
│  data-dir/<peer_id>.db                  │
└─────────────────────────────────────────┘
```

**默认 peer：** `local-main`  
配置项：`SHELL_PEER_ID`（默认 `local-main`）、`SHELL_TOKEN`、`SHELL_HOST=127.0.0.1`、`SHELL_PORT`（建议 `8757`，避免与现有 sidecar `8756` 冲突；若合并进原 server 则用路由前缀 `/v1`）。

**推荐实现策略（二选一，优先 A）：**

- **A（推荐）：** 扩展现有 `python -m extra_brain.server`，增加 `/v1/*` 路由与可选静态 UI 目录。  
- **B：** 新模块 `extra_brain.shell_server`，内部 import 同一套 brain API，仍读同一 `data-dir`。

禁止：Node 里再实现一套记忆逻辑。

### T1. API：Health 与鉴权

**端点**

```http
GET /v1/health
Headers: Authorization: Bearer <token>   # 可对 health 放宽为无 token，但需文档写明
```

响应示例：

```json
{
  "ok": true,
  "version": "0.13.0",
  "peer_id": "local-main",
  "read_write": true,
  "data_dir": "..."
}
```

- [ ] 除 health 外所有 `/v1/*` 校验 `Authorization: Bearer` 或 `X-Shell-Token`  
- [ ] token 错误 → `401`  
- [ ] 绑定 `127.0.0.1`（配置强制，禁止默认 `0.0.0.0`）

- [ ] 直接调用现有 `build_injection`  
- [ ] 不写库

### T3. API：consolidate

```http
POST /v1/consolidate
Content-Type: application/json

{
  "peer_id": "local-main",
  "session_id": "shell-20261106-001",
```

- [ ] 无 Key 时行为与现网一致（只读/降级错误码明确）  
- [ ] 写入目标 peer 的 db

### T4. API：chat（核心）

```http
POST /v1/chat
{
  "peer_id": "local-main",
  "session_id": "shell-...",
  "message": "用户本句",
  "history": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "auto_inject": true,
  "model": null
}
```

**服务端逻辑（必须）：**

1. 若 `auto_inject`：用 `message` + 可选 recent 调用 `build_injection`  
2. 拼 system：人设（若有）+ 注入文本 + 安全规范（从 user_config 读）  
3. 调现有 LLM（DeepSeek 等，与 consolidate 同一套客户端配置）  
4. 返回：

```json
{
  "reply": "助手回复",
  "session_id": "...",
  "injected": true,
  "inject_token_estimate": 500,
  "usage": {}
}
```

- [ ] **本版可不在服务端自动 consolidate**（由 UI 按钮或客户端策略调用 T3），避免每句都抽记忆烧配额；UI 提供「结束本段并记住」  
- [ ] 可选配置 `auto_consolidate_every_n` 默认 `0`（关）  

---

### T5. Web UI 最小页

**路径：** `shell_web/index.html`（或 `src/extra_brain/static/shell/`）由 server 挂载在 `/` 或 `/shell/`

**必须有的 UI 元素：**

| 元素 | 行为 |
|------|------|
| 消息列表 | user / assistant 气泡 |
| 输入框 + 发送 | 调 `POST /v1/chat` |
| 按钮「预览将注入的记忆」 | 调 inject_preview，侧栏或折叠区显示 |
| 按钮「记住以上对话」 | 把当前 session history 调 consolidate，Toast 成功/失败 |
| 连接状态 | health 轮询或首屏检查 |
| Token 输入 | localStorage 存 shell token（首次粘贴） |

**不要：** 登录系统、Markdown 炫技编辑器、多主题、移动端完整适配（基础可用即可）。
